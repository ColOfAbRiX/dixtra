final class AssignmentRenderer(ctx: RenderContext, terms: TermRenderer)

Renders definitions with a header kept as written followed by = and a body: val / lazy val, var, parameterless def and given aliases.

Renders definitions with a header kept as written followed by = and a body: val / lazy val, var, parameterless def and given aliases.

The body follows the rules of com.colofabrix.scala.dixtra.render.term.BodyLayout, placed by the body setting of its keyword (body.val, body.lazy-val, body.var, body.def, body.given-alias): it drops below the = when it does not fit or renders multiline, and a newline after = is an author signal for it. Only a newline after the = counts: a break earlier in the header (e.g. after an annotation) is not a signal. The header can be padded so that the = lines up with the definitions around it (see com.colofabrix.scala.dixtra.render.Alignment).

final class DefRenderer(ctx: RenderContext, terms: TermRenderer, assignments: AssignmentRenderer, signatures: SignatureRenderer)

Renders method definitions (def): a signature (see SignatureRenderer) followed by = and a body (see com.colofabrix.scala.dixtra.render.term.BodyLayout).

Renders method definitions (def): a signature (see SignatureRenderer) followed by = and a body (see com.colofabrix.scala.dixtra.render.term.BodyLayout).

Of the Tier 1 break-points, the newline after = is taken first when that is stable: a body that does not fit after = drops onto the next line with the signature kept on one line, as long as the body renders the same once below = (where the newline counts as an author signal on the next run). Otherwise the whole signature = body line decides whether the parameters explode, so the body can stay on the ): Type = line. body.def places the body; with always-join a body below the = moves up only when the whole definition fits on one line, and with always-break the body is always below the =. The signature can be padded so that the = lines up with the definitions around it.

A signature holding comments that cannot be re-attached is kept as written, and a parameterless def is rendered like a val by the assignment renderer. A given alias with parameters is laid out like a def, and an abstract def is its signature alone.

final class ImportRenderer(ctx: RenderContext)

Renders import and export clauses.

Renders import and export clauses.

The selectors keep their spelling (_ / *, => / as): only the spaces inside the braces, the braces around a single selector (braces.imports) and the line breaks change. A clause with a single importer that does not fit packs its selectors onto as few lines as fit; a clause with several importers, or with a comment, is never broken.
